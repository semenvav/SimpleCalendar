# SimpleCalendar

Семейный календарь для домашнего сервера: берёт события из Baikal по CalDAV, кэширует их у себя
и показывает на веб-странице, рассчитанной на настенный планшет.

Работает только внутри домашней сети. Наружу не публикуется.

**Статус: этапы M1–M3 — чтение, запись и повторяющиеся события, плюс механизм раскладок из M4.
Из M5 готова серверная часть интеграций: погода, Home Assistant, Immich — на экран они пока не
выведены.**
Что осталось — см. [Что дальше](#что-дальше).

## Что уже работает

- Обнаружение календарей в Baikal (`current-user-principal` → `calendar-home-set` → коллекции)
- Инкрементальная синхронизация по RFC 6578 с двумя запасными вариантами
- Корректные повторяющиеся события: `RRULE`, `EXDATE`, `RDATE`, перенесённые экземпляры,
  переходы на летнее время, события на весь день
- Виды: месяц, **два месяца рядом**, неделя, список
- Цвета календарей, фильтр по календарям, карточка события по касанию
- Перезагрузка страницы не сбрасывает вид: формат запоминается на устройстве, открытый период —
  до закрытия вкладки. Потянуть страницу вниз для обновления (pull-to-refresh) нельзя
- **Создание, правка и удаление событий** прямо с планшета — касание пустого дня создаёт событие
- **Повторяющиеся события**: каждый день, неделю, две недели, месяц, год — до какого-то дня или без
  конца. Правка и удаление с выбором «только это / это и все следующие / все события серии».
  Время серии переживает переход на летнее и зимнее время
- Правила, которые пишут телефоны («второй вторник месяца»), читаются правильно и при правке
  остаются как были, пока их не трогают
- **Одновременная правка с телефона не теряется**: запись идёт с `If-Match`, и при расхождении
  появляется понятное сообщение вместо тихой перезаписи чужих изменений
- Правка чужого события сохраняет всё, что мы не показываем: будильники, участников, категории
- **Несколько раскладок**: новая версия внешнего вида живёт рядом со старой, каждое устройство
  помнит свою — см. [Раскладки](#раскладки)
- Работает при недоступном Baikal — показывает последние известные данные
- **Интеграции на сервере**: погода (Open-Meteo), состояния сущностей Home Assistant, фото из
  альбомов Immich — отдаются через `/api/integrations`, ключи не покидают сервер. См.
  [Интеграции](#интеграции)
- **Выход наружу через прокси**: `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY` — для контейнера во
  внутренней сети со Squid

Чего пока нет: переноса события между календарями и настройки календарей из интерфейса.

## Быстрый старт

### 1. Настроить Baikal

Схема — одна учётная запись, несколько календарей:

1. Создайте пользователя, например `family`
2. Создайте по календарю на человека: «Мама», «Папа», «Дети»
3. Цвета и отображаемые имена можно задать в Baikal, но их же можно переопределить у нас —
   синхронизация ваши правки не затирает

Тип аутентификации (Digest или Basic) настраивать не нужно: схема определяется автоматически при
первом обращении. Baikal по умолчанию использует Digest.

### 2. Запустить

Образ собирает GitHub Actions при каждом push и публикует в `ghcr.io/semenvav/simplecalendar`.
На сервере ничего не собирается — нужны только `docker-compose.yml` и `.env`:

```bash
mkdir -p /opt/calendar && cd /opt/calendar
curl -fsSLO https://raw.githubusercontent.com/semenvav/SimpleCalendar/master/docker-compose.yml
curl -fsSL https://raw.githubusercontent.com/semenvav/SimpleCalendar/master/.env.example -o .env
# отредактируйте .env: хост, адрес и пароль Baikal, тег образа
docker compose pull && docker compose up -d
```

Все значения, относящиеся к конкретной установке, — хост, пароль, имя экземпляра — живут только в
`.env`, который не попадает в репозиторий. `docker-compose.yml` без `SC_HOSTNAME` не запустится.

Обновление — вручную, когда и куда нужно: поменяйте `SC_IMAGE_TAG` в `.env` и повторите
`docker compose pull && docker compose up -d`.

| Тег | Что это |
|---|---|
| `latest` | последняя сборка master |
| `<ветка>` | последняя сборка ветки — удобно для тестового экземпляра |
| `sha-1a2b3c4` | ровно один коммит — чтобы семейный экземпляр не менялся без вашего ведома |
| `0.2.0` | релиз, если запушить тег `v0.2.0` |

Один раз после первой сборки сделайте пакет публичным: на GitHub → Packages → `simplecalendar` →
Package settings → Change visibility → Public. Новые пакеты в GHCR создаются приватными даже из
публичного репозитория, и без этого серверу для `pull` понадобится логин.

**Несколько экземпляров.** Семейный и тестовый живут рядом: у каждого своя папка со своим `.env`
и свой `COMPOSE_PROJECT_NAME`. От имени проекта зависят контейнер, том с данными (`<имя>_data`)
и маршрут в Traefik, так что экземпляры друг другу не мешают. Тестовому дайте отдельного
пользователя в Baikal — иначе тестовые правки попадут в семейный календарь.

**Traefik.** Порты на хосте не публикуются: контейнер подключается к внешней Docker-сети Traefik
(`SC_TRAEFIK_NETWORK`) и доступен только через неё. Имя сети можно подсмотреть у любого сервиса,
который уже работает за Traefik:

```bash
docker inspect <контейнер> --format '{{range $k, $v := .NetworkSettings.Networks}}{{$k}} {{end}}'
```

Том с данными хранит только кэш и ваши имена и цвета календарей — сами события в Baikal, так что
его потеря стоит одной пересинхронизации.

На планшете просто откройте ваш адрес во вкладке браузера. Приложение не делает ничего за
пределами обычной вкладки: яркостью, сном и пробуждением экрана управляет Android.

## Раскладки

Внешний вид собран в раскладки. Сейчас она одна — «Классика». Новые версии по отзывам семьи
добавляются рядом, а не вместо старой, чтобы их можно было сравнить на настоящем планшете.

- Раскладка запоминается на устройстве. Когда их больше одной, в панели появляется переключатель
- Переключить устройство можно и адресом: откройте один раз `https://<ваш хост>/?layout=<id>` —
  дальше оно открывается в этой раскладке, а параметр из адреса убирается сам
- Как сделать новую версию — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md#раскладки)

## Интеграции

То, что показывается рядом с календарём, но живёт в других сервисах. Каждая интеграция выключена,
пока не заданы её настройки (см. [Настройки](#настройки) и `.env.example`). Сервер сам опрашивает
сервис по расписанию и хранит последний удачный ответ, а браузер читает только нашу копию — поэтому
токены и ключи остаются на сервере, а упавший сервис не гасит угол экрана: показывается последнее,
что удалось получить.

| Интеграция | Что отдаёт | Как часто | Что нужно |
|---|---|---|---|
| `weather` | Погода сейчас и на 16 дней: температура, ощущается как, влажность, ветер, вероятность осадков, условие (`sunny`, `rainy`, …) | 30 мин | Координаты дома. Ключ не нужен |
| `homeassistant` | Состояния выбранных сущностей в заданном порядке, с именем, единицей и всеми атрибутами | 1 мин | Адрес, долгоживущий токен, список сущностей |
| `immich` | 100 случайных фото из выбранных альбомов, заново каждый час; сами картинки — через наш сервер | 1 час | Адрес, API-ключ с правами `asset.read` и `asset.view`, id альбомов |

Условия погоды названы словарём Home Assistant: `sunny`, `clear-night`, `partlycloudy`, `cloudy`,
`fog`, `rainy`, `pouring`, `snowy`, `lightning-rainy`, `hail`.

Immich отдаёт только фото из альбомов, а не из всей библиотеки: случайная выборка из семейного
архива рано или поздно повесит на кухню скриншот или скан паспорта. Альбом — это выбор человека.
Отдаются только картинки из текущей выборки: через календарь нельзя достать из Immich что-то ещё.

На экран интеграции пока не выведены — где и как их показывать, решает раскладка.

### Выход наружу через прокси

Если контейнер стоит во внутренней Docker-сети без выхода в интернет, а наружу ходит через Squid
с белым списком, задайте в `.env` (или прямо в `environment` compose-файла):

```
HTTP_PROXY=http://squid:3128
HTTPS_PROXY=http://squid:3128
NO_PROXY=localhost,127.0.0.1,172.16.0.0/12,baikal,homeassistant,immich-server
```

Правила — те же, что у curl и Go, то есть у большинства соседних контейнеров:

- `HTTPS_PROXY` отвечает за `https://`-адреса (через `CONNECT`), `HTTP_PROXY` — за `http://`.
  Одна не подменяет другую
- В `NO_PROXY` — имена, IP-адреса и подсети через запятую. Имя покрывает и поддомены:
  `.example.com` и `example.com` оба пропускают `photos.example.com`
- **Подсеть срабатывает только для адресов, записанных цифрами.** Имя контейнера в IP не
  разрешается, поэтому Baikal, Home Assistant и Immich, если к ним обращаются по имени, надо
  перечислить по имени. Иначе запрос к ним уйдёт в Squid
- `localhost` всегда идёт напрямую
- Прокси — только `http://` и без логина и пароля в адресе; иначе приложение не запустится и
  объяснит почему

Правила действуют на все запросы приложения, включая CalDAV. При старте в логе видно, что куда
пойдёт:

```
Outgoing proxy: http http://squid:3128, https http://squid:3128, direct for: localhost,...
CalDAV source: http://baikal/dav.php/ (user family, direct)
Integration 'weather': https://api.open-meteo.com (via http://squid:3128), every 30m
```

В белый список Squid для погоды нужен `api.open-meteo.com`.

Дополнительные сети — ту, где стоит Squid, сети Home Assistant и Immich — удобно подключить в
`docker-compose.override.yml` рядом с `docker-compose.yml`: compose подхватывает его сам, а
общий файл остаётся без изменений.

```yaml
services:
  app:
    networks:
      - egress
      - homeassistant
networks:
  egress:
    external: true
  homeassistant:
    external: true
```

## Разработка

Нужны JDK 21 и Node 22. Gradle подтянется сам через wrapper.

```bash
# Терминал 1 — сервер (читает .env из корня проекта)
./gradlew run

# Терминал 2 — фронтенд с горячей перезагрузкой, проксирует /api на localhost:8080
cd frontend && npm install && npm run dev
```

Фронтенд откроется на `http://localhost:5173`.

Если Baikal под рукой нет, поднимите временный:

```bash
docker compose -f docker-compose.dev.yml up -d
# откройте http://localhost:8800, пройдите мастер установки, создайте пользователя и календари
# затем в .env: SC_CALDAV_URL=http://localhost:8800/dav.php/
```

Состояние этого Baikal лежит в `./.dev` и игнорируется git — удалите каталог, чтобы начать заново.

### Проверка собранного образа

```bash
docker build -t simple-calendar:test .
docker run --rm --network simplecalendar_default -p 8094:8080 \
  -e SC_CALDAV_URL=http://baikal/dav.php/ \
  -e SC_CALDAV_USERNAME=family -e SC_CALDAV_PASSWORD=... \
  -e SC_TIMEZONE=Asia/Jerusalem simple-calendar:test
```

`simplecalendar_default` — сеть, которую создаёт `docker-compose.dev.yml`; внутри неё Baikal
доступен по имени `baikal`.

### Тесты

```bash
./gradlew test              # 142 теста: повторения, пояса, CalDAV, запись, Baikal, прокси, интеграции
cd frontend && npm run typecheck
```

Часть тестов — round-trip против настоящего Baikal: Testcontainers поднимает его в Docker из
образа `ckulka/baikal:0.10.1-nginx`. Без Docker эти тесты пропускаются, остальные проходят как
обычно.

То же самое GitHub Actions запускает на каждый push (`.github/workflows/ci.yml`); образ
публикуется, только если тесты прошли. Pull request'ы, в том числе из форков, только тестируются.

Корпус `.ics`-фикстур лежит в `src/test/resources/fixtures/`. Если найдёте событие, которое
отображается неправильно, — сохраните его `.ics` туда и напишите тест: именно так этот код и
защищён от регрессий.

## Настройки

Все переменные окружения, значения по умолчанию в скобках.

| Переменная | Назначение |
|---|---|
| `SC_CALDAV_URL` | Корень DAV в Baikal, например `http://baikal/dav.php/`. Можно указать сразу principal или calendar-home — обнаружение спустится от того, что дано |
| `SC_CALDAV_USERNAME` | Пользователь Baikal |
| `SC_CALDAV_PASSWORD` | Пароль |
| `SC_TIMEZONE` | Часовой пояс дома (`Asia/Jerusalem`). Определяет, что такое «сегодня» и как показывать события без пояса. В compose по умолчанию `Asia/Jerusalem`, при локальном запуске — системный |
| `SC_SYNC_INTERVAL_SECONDS` | Как часто спрашивать Baikal об изменениях (`60`) |
| `SC_PORT` / `SC_HOST` | Куда слушать (`8080` / `0.0.0.0`) |
| `SC_DATA_DIR` | Каталог с кэшем SQLite (`/data` в контейнере, `./data` локально) |
| `SC_STATIC_DIR` | Собранный фронтенд. В контейнере задан; локально не задавайте — UI отдаёт Vite |
| `SC_DEV_CORS` | Разрешить кросс-доменные запросы с dev-сервера Vite (`false`). В продакшене не включать |
| `SC_LOG_LEVEL` | `INFO`, поставьте `DEBUG` чтобы видеть тайминги синхронизации и разворачивания |
| `HTTP_PROXY` / `HTTPS_PROXY` | Прокси для `http://` и `https://`-адресов, например `http://squid:3128`. Пусто — напрямую. См. [Выход наружу через прокси](#выход-наружу-через-прокси) |
| `NO_PROXY` | Куда ходить без прокси: имена, IP, подсети через запятую |
| `SC_WEATHER_LATITUDE` / `SC_WEATHER_LONGITUDE` | Координаты дома для погоды, через точку. Обе заданы — погода включена |
| `SC_HA_URL` | Адрес Home Assistant, например `http://homeassistant:8123`. Задан — интеграция включена |
| `SC_HA_TOKEN` | Долгоживущий токен: профиль → Безопасность в Home Assistant |
| `SC_HA_ENTITIES` | Сущности через запятую: `sensor.living_room_temperature,person.mama` |
| `SC_IMMICH_URL` | Адрес Immich, например `http://immich-server:2283`. Задан — интеграция включена |
| `SC_IMMICH_API_KEY` | API-ключ Immich с правами `asset.read` и `asset.view` |
| `SC_IMMICH_ALBUMS` | id альбомов через запятую — последняя часть адреса альбома в Immich |
| `SC_HOSTNAME` | Только для compose, обязательна: хост, по которому Traefik отдаёт приложение |
| `SC_TRAEFIK_NETWORK` | Только для compose: внешняя Docker-сеть, к которой подключён Traefik (`traefik`) |
| `SC_IMAGE_TAG` | Только для compose: какую сборку запускать (`latest`), см. таблицу тегов выше |
| `COMPOSE_PROJECT_NAME` | Только для compose: имя экземпляра; по умолчанию — имя папки |

Переменные окружения имеют приоритет; файл `.env` в рабочем каталоге заполняет остальное, поэтому
`./gradlew run` и `docker compose` читают одни и те же настройки.

## API

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/api/health` | Состояние, версия, статус синхронизации |
| `GET` | `/api/calendars` | Список календарей |
| `PATCH` | `/api/calendars/{id}` | Свои имя, цвет, видимость, порядок. Пустая строка сбрасывает переопределение |
| `GET` | `/api/events?from=&to=&calendars=` | Развёрнутые экземпляры за период. Даты — ISO, голая дата читается в часовом поясе дома |
| `POST` | `/api/events` | Создать событие. В теле `calendarId`, `title`, `allDay`, `start`, `end`, необязательный `repeat` |
| `PATCH` | `/api/events?id=&scope=` | Изменить событие. `id` — тот, что вернул `GET /api/events`; `scope` — `this`, `following` или `all` (по умолчанию) |
| `DELETE` | `/api/events?id=&scope=` | Удалить событие; `scope` — как у `PATCH` |
| `POST` | `/api/sync` | Синхронизироваться немедленно |
| `GET` | `/api/integrations` | Включённые интеграции: когда получен последний ответ, последняя ошибка |
| `GET` | `/api/integrations/{id}` | Последний удачный ответ интеграции в поле `data`, время его получения и последняя ошибка |
| `GET` | `/api/integrations/immich/photos/{assetId}` | Фото (превью ~1440 px) из текущей выборки Immich |

В запросах на запись `end` **исключающий**, как и в ответах на чтение: событие на 10 сентября —
это `start=2026-09-10, end=2026-09-11`. Время без пояса (`2026-09-15T19:00`) читается в часовом
поясе дома.

`repeat` — `{"frequency": "WEEKLY", "interval": 1, "until": "2026-12-31"}`, где `until`
включительный и необязательный. `{"frequency": "NONE"}` отменяет повтор, а если `repeat` не
прислать, правило события остаётся как было — в том числе такое, которое форма показать не может.
Для одиночного события `scope` ни на что не влияет.

Коды ответов: `409` — событие изменили в другом месте, `403` — календарь только для чтения,
`404` — события или повторения уже нет, `400` — запрос не прошёл проверку (например, смена
правила повтора для одного экземпляра).

## Структура

```
src/main/kotlin/dev/simplecalendar/
├── caldav/      клиент CalDAV поверх Ktor HttpClient + разбор WebDAV XML
├── ical/        iCalendar: разбор, повторения, правка серий, VTIMEZONE  ← ядро, сюда с осторожностью
├── store/       SQLite: схема, миграции, репозитории
├── sync/        фоновый цикл синхронизации
├── service/     запросы событий за период и запись
├── integrations/ погода, Home Assistant, Immich — по пакету на каждую, и общий опрос
├── net/         прокси для исходящих запросов
├── api/         маршруты Ktor и DTO
└── config/      настройки из окружения

frontend/src/
├── app/         состояние и действия, общие для всех раскладок; карточка и форма события
├── layouts/     раскладки — реестр, переключатель и по папке на каждую  ← внешний вид здесь
├── calendar/    адаптер к библиотеке календаря  ← единственное место, знающее о ней
├── components/  карточка события, форма, диалог выбора
├── lib/         даты, правила повтора, запоминание на устройстве
└── views.ts     виды, диапазоны запросов, заголовки
```

Библиотека календаря (Event Calendar) изолирована в `frontend/src/calendar/`. Заменить её или
перейти на свои компоненты — значит переписать два файла, а не приложение.
